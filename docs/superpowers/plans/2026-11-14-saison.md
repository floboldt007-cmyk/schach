## Ziel
Eine Saison dauert 8 Wochen. Die hoechste Liga-Stufe einer Saison wird ein dauerhaftes Abzeichen. Wer am Saisonende
bei Crownmate I steht (Stufe 17), bekommt den Titel "Crownmaster Season N". Danach sinkt die Stufe weich um 3
(nie unter Squire III = 0), aber nur bei Konten mit mindestens einer Ligawoche in der Saison. Die Elo wird nie
zurueckgesetzt. Top 10 und Top 100 nach Elo bekommen einen Saison-Titel, wenn sie in der Saison mindestens 20
gewertete Online-Partien hatten. Der Gegner sieht auf der Visitenkarte die aktuelle Liga mit Rang-Symbol (gibt es
schon), NUR das beste Saison-Abzeichen und einen Saison-Titel nur, wenn der Spieler ihn selbst waehlt.

## Entwurf Server (neue Dateien, VORSCHLAG, NOCH NICHT EINGESPIELT, Einspielen Flo, nie Claude)
`supabase/saison-schema.sql`:
- `saison_konstanten()` jsonb: `start` 2027-01-04 (Montag der Saison 1), `wochen` 8, `reset` 3, `top` [10, 100],
  `mindest_partien` 20. Teilnehmer und Hoechststufe nur aus Gruppen der Liga 'online' (F3).
- `saison_nummer(woche date)` int: 0 vor dem Start, sonst `floor((woche - start) / 56) + 1`.
- Tabelle `saison_abrechnungen(saison int primary key, am timestamptz)`: jede Saison genau einmal.
- Tabelle `saison_abzeichen(user_id -> auth.users on delete cascade, saison int, stufe int 0..17, primary key
  (user_id, saison))`.
- Tabelle `saison_titel(user_id -> auth.users on delete cascade, saison int, art text in ('crownmaster','top10',
  'top100'), primary key (user_id, saison, art))`.
- Tabelle `saison_wahl(user_id pk -> auth.users on delete cascade, titel text null)`: der selbst gewaehlte Titel
  als ID `crownmaster-s<N>` / `top10-s<N>` / `top100-s<N>`.
- Alle Tabellen RLS an, keine Policies, `revoke all` von anon, authenticated, public (Muster kronen-schema Z. 104-114).
- `saison_abrechnen()` (security definer, search_path ''): nimmt die Sperre `liga-abrechnen` (dieselbe, also keine
  zweite Reihenfolge), rechnet JEDE beendete, noch nicht abgerechnete Saison s < saison_nummer(heute) der Reihe nach:
  1. Teilnehmer = Konten mit einer Zeile in liga_mitglieder einer Woche der Saison.
  2. Hoechststufe = greatest(kronen_stand.stufe, max(liga_gruppen.stufe ihrer Saisonwochen)) -> saison_abzeichen.
  3. Crownmaster: Teilnehmer mit kronen_stand.stufe = 17 -> saison_titel 'crownmaster'.
  4. Top: Konten mit mindestens 20 Buchungen quelle 'online' in Saisonwochen, rank() ueber kronen_stand.elo desc;
     rang <= 10 -> 'top10', sonst rang <= 100 -> 'top100' (ein Titel je Konto und Saison, der bessere).
  5. Reset: Teilnehmer stufe := greatest(0, stufe - 3).
  6. insert saison_abrechnungen (on conflict do nothing; vorher Pruefung, damit nichts doppelt laeuft).
  Pause ueber mehrere Saisons: nur die Saison mit Ligawochen setzt zurueck, also genau ein Reset; ein Konto ohne
  Partien bekommt nichts. Saisons vor dem Start (Nummer 0) werden nie abgerechnet.
- `saison_mein_stand()` (authenticated): aktuelle Nummer, Ende (Datum), Woche x von 8, eigene Hoechststufe dieser
  Saison bisher, eigene Abzeichen und Titel (alle Saisons), gewaehlter Titel. Ruft vorher kronen_stand_sichern.
- `saison_titel_waehle(titel text default null)`: null loescht; sonst nur ein eigener Titel, sonst `SAISON_TITEL`.
- `saison_karte_der_partie(partie uuid)`: fuer w und s je `{ abzeichen: {saison, stufe} | null, titel: id | null }`,
  nur das beste Abzeichen (hoechste Stufe, bei Gleichstand die juengste Saison), Titel nur aus saison_wahl und nur,
  wenn er noch in saison_titel steht. Unbeteiligte: `SAISON_KEINE_PARTIE`. Keine Saison-Liste, keine Kronen, keine
  Partienzahl.
- revoke von public/anon, grant execute nur der drei Nutzer-Funktionen an authenticated; saison_abrechnen nur intern.

Haken in `liga_abrechnen()` in `supabase/kronen-schema.sql` UND `supabase/zwei-ligen-schema.sql` (live Fassung), je zwei Zeilen:
- im Fruehausstieg vor `return`: `if to_regprocedure('public.saison_abrechnen()') is not null then perform
  public.saison_abrechnen(); end if;` (Saison endet, aber keine Woche offen).
- nach der Wochen-Schleife, VOR `liga_alte_wochen_loeschen()`: dieselbe Zeile.
So laeuft die Saison immer NACH der Abrechnung ihrer letzten Woche und VOR der ersten Gruppe der neuen Saison. Ohne
saison-schema.sql bleibt das Verhalten gleich (Test).

`supabase/daten-schema.sql`: Block `to_regclass('public.saison_abzeichen')` fuer die Datenauskunft (Abzeichen, Titel,
Wahl), Muster Z. 428; `daten-auskunft-zurueck.sql` pruefe ich beim Bau, ob er die Funktion neu schreibt.
`supabase/saison-zurueck.sql`: Funktionen und Tabellen weg; der Haken in liga_abrechnen bleibt harmlos (to_regprocedure
null). `supabase/saison-rls-test.sql`: Probe fuer den SQL-Editor (anon abgewiesen, Tabellen nicht lesbar).
